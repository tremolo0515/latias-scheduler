# Pokemon Sleep イベント管理ツール 開発仕様書

> 作成日: 2026-04-03

---

## 1. プロジェクト概要

Pokemon Sleep のイベント（約2週間）を効率よく攻略するための管理ツール。  
アイテムの在庫管理・使用提案・イベント効果の確認・進め方の保存・SNS共有を一元管理する。

---

## 2. 技術スタック

| 項目 | 採用技術 |
|---|---|
| フレームワーク | React + TypeScript + Vite |
| スタイル | Tailwind CSS |
| データ保存 | IndexedDB（Dexie.js） |
| 画像エクスポート | html2canvas |
| カレンダー | カスタム実装（14日グリッド） |
| ホスティング | 未定（Vercel / GitHub Pages 候補） |

- **データはローカルのみ**（ログイン不要・クラウド同期なし）
- **ブラウザで動作**（PC・スマホ両対応のレスポンシブ設計）

---

## 3. 画面構成


---

## 4. 画面別仕様

### 4-1. ダッシュボード

- 現在進行中イベントのバナー（残り〇日）
- **今日のタスク**（使うべきアイテム・やること）
- イベント効果のクイック確認（乗算ボーナス等をバッジ表示）

---

### 4-2. イベント設定

| フィールド | 内容 |
|---|---|
| イベント名 | テキスト入力 |
| 開始日〜終了日 | 日付ピッカー（デフォルト14日） |
| イベント効果 | 複数登録（名前・種別・倍率・発動条件） |
| 乗算効果 | 馬効果など特殊ボーナスを別管理 |
| メモ | 自由記述 |

---

### 4-3. カレンダービュー

- 14日間をグリッド表示
- 各日セルに表示：
  - 曜日・日付
  - その日の推奨アイテム（使用提案から連動）
  - ユーザーの進め方メモ
  - 完了チェック
- **週末 / 平日で色分け**（使えるアイテムが変わるため）

---

### 4-4. アイテム在庫 + 使用提案

**アイテム登録フォーム**

```
名前 / 個数 / 効果種別 / 効果量
```

**使用提案ロジック（ルールベース）**

- 残りイベント日数 ÷ 在庫数 → 1日あたりの使用目安
- 乗算ボーナスが高い日（週末・イベント後半）に強いアイテムを割り当て
- 「◯曜日に〇個使うとベスト」と提案表示

---

### 4-5. SNSエクスポート（週間スケジュール画像）

- 今週7日分のカードをHTML描画 → `html2canvas` でPNG出力
- 表示内容：曜日・使うアイテム・ひとことメモ
- Pokemon Sleep らしいデザイン（青・星テーマ）
- ダウンロード or クリップボードコピーに対応

---

## 5. データモデル

```typescript
// イベント
type PokeSleepEvent = {
  id: string
  name: string
  startDate: string     // ISO date (YYYY-MM-DD)
  endDate: string
  effects: EventEffect[]
  memo: string
}

// イベント効果
type EventEffect = {
  id: string
  name: string
  type: 'multiplier' | 'bonus_item' | 'exp' | 'shard' | 'other'
  value: number         // 倍率 or 個数
  condition: string     // 発動条件の説明テキスト
}

// アイテム在庫
type Item = {
  id: string
  name: string
  quantity: number
  effectType: string
  effectValue: number
}

// 日別プラン（14日分）
type DayPlan = {
  eventId: string
  date: string          // ISO date
  plannedItems: { itemId: string; quantity: number }[]
  note: string          // 進め方メモ（自由記述）
  isCompleted: boolean
}
```

## 6. 開発フェーズ

| フェーズ | 内容 | 目的 |
|---|---|---|
| **Phase 0** | **v0.dev でモック作成** | **画面仕様の確定** |
| Phase 1 | イベント設定・カレンダー表示の実装 | コア機能 |
| Phase 2 | アイテム在庫登録・使用提案の実装 | 提案機能 |
| Phase 3 | ダッシュボード・今日のタスクの実装 | UX向上 |
| Phase 4 | SNS画像エクスポートの実装 | 共有機能 |
| Phase 5 | イベント効果の乗算計算UIの実装 | 高度な分析 |

### Phase 0 の進め方（v0.dev モック）

1. 各画面のプロンプトを v0.dev に投入
2. 生成されたUIを確認・調整してデザインを確定
3. 確定したコンポーネントをそのままPhase 1以降に取り込む

**モック作成対象画面（優先順）**

1. カレンダービュー（最重要・複雑）
2. アイテム在庫 + 使用提案
3. ダッシュボード
4. イベント設定フォーム
5. SNSエクスポートプレビュー
