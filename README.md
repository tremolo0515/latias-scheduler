# latias-scheduler（伝説イベント管理表）

ポケモンスリープの伝説ポケモンイベント（約2週間、うもう/いでんし等の資材交換所付き）を
効率よく攻略するための、在庫管理・スロット配置ツール。

## 解決する課題

イベント期間中に配布・交換で手に入る「おこう」「サブレ」をどの日に何個使うかは、
週末・特別デーなどタイミングによって効率が変わる。紙やメモでは在庫と配置の対応が
崩れやすく、配置し忘れ・二重配置に気づきにくい。

## 想定ユーザー

イベントを毎回攻略している自分自身（作者）。他のプレイヤーが使っても構わないが、
個人の攻略メモを置き換える用途を最優先に作っている。

## MVPスコープ

- イベントごとの在庫入力（交換所での交換 → 自動で在庫加算）
- 14日間 + イベント後2日 + 持ち越し1日のカレンダーへ、ドラッグ&ドロップ／タップでアイテムを配置
- 日付ごとのロック（確定した配置を誤操作から保護）
- 分割睡眠（1日2回睡眠）時の2回目スロット
- 日付ごとのメモ・全体メモ
- 複数イベントの切り替え（データはイベントIDごとにlocalStorageで独立）
- スマホ対応レイアウト（グリッド⇔縦リスト）

## 非スコープ

- ログイン・クラウド同期（ブラウザのlocalStorageのみ、端末をまたいだ共有はしない）
- 自動配置提案ロジック（過去に実装したが精度が実用に届かず現在は無効化。データは
  git履歴に残っているので、需要が戻れば復活させる）
- SNS共有・画像エクスポート
- 交換所の確定値が発表前でも自動取得すること（毎回、開催前は過去イベント同等の値で
  仮置きし、開催後に手動更新する運用）

## 技術スタック

- Next.js（App Router）+ TypeScript
- Tailwind CSS v4
- データ保存: localStorage（イベントIDごとにキーを分離）
- E2E: Playwright（`npm run test:e2e` 相当は `npx playwright test`）
- ユニットテスト: Vitest（`lib/data/` の純粋関数を対象、`npm run test`）

## 新しいイベントを追加する手順

1. `lib/data/items.ts` に新アイテムがあれば追記
2. `lib/data/events.ts` の `EVENTS` 配列末尾にイベント定義を追記（末尾に追加すると
   自動的にデフォルト表示になる）
3. 画像が未入手なら `public/img/` に仮画像を置き、パスだけ通しておく
4. 交換所の詳細が未発表なら、直近の同種イベントと同じ構造・価格で仮置きし、
   開催後に確定値へ更新する

詳しい設計判断は `docs/implementation-plan-multi-event.md`（イベント多重対応の基盤）・
`docs/implementation-plan-mewtwo-event.md`（直近の追加例）を参照。
